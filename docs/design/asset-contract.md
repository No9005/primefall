# Asset Contract

This contract lets the prototype be built with placeholder assets while the final art is produced in parallel. A final asset replaces a placeholder by using the **same file name, canvas size and pivot**. Nothing in the game code may depend on whether an asset is a placeholder.

Placeholders live in `apps/web/public/assets/` and are generated by `docs/design/tools/generate_placeholders.py` (run `python3 docs/design/tools/generate_placeholders.py` from the repository root; it needs Pillow).

## Conventions

- Format: transparent PNG, 32-bit alpha, no baked background.
- Projection: 2:1 isometric. One tile diamond is **128 x 64 px**. One consistent pixels-per-unit scale for everything.
- Light comes from the top left; contact shadows are subtle and part of the sprite.
- The pivot is given as a Pixi anchor `(x, y)` in the manifest. Hero anchor `(0.5, 1)` is the bottom vertex of the footprint diamond of the Hero's tile.
- Heroes face south-east. Other facings are produced by mirroring (`scale.x = -1`); directional variants are out of scope for the MVP.
- Squad colour is not baked into sprites. The renderer draws a ring under each Hero (own and allied Squad teal, enemy Squad red).
- Hidden, Marked, Slow and Shield are separate VFX sprites or filters, not baked pose variants.
- Animation frames (later) share canvas size, padding and pivot with their pose.

## Terrain (no sprites)

Floor, Walls, Cover, the Overwatch Nest, the Prime Zone tint and the Spawn markers are not assets. They are drawn as shapes computed from the grid and a view angle (`apps/web/src/terrain.ts`), with all colours in `apps/web/src/terrain-style.ts`. The tile diamond is still 128 x 64 px, so Heroes and VFX keep the same scale. Final terrain art would come as a change to the terrain style or a later asset contract entry, not as tile or prop PNGs.

## Heroes (canvas 128 x 192, anchor 0.5, 1; feet 8 px above the bottom edge)

Path: `heroes/<class>/<pose>`, class one of `bruiser`, `controller`, `assassin`.

| Pose | Classes | Used for |
|---|---|---|
| `idle` | all | Planning, waiting |
| `move` | all | Move actions |
| `attack_ranged` | all | Most Attack cards |
| `block_shield` | all | Block 2, Shield effects |
| `utility_cast` | all | Utility cards, Overdrives |
| `hit` | all | Deck Damage feedback |
| `exhausted` | all | Exhaustion |
| `heavy_attack`, `breach_charge_throw` | bruiser | Slam Shot family, Breach Charge |
| `drone_deploy`, `cover_deploy` | controller | Scout Drone, Deploy Cover |
| `precision_aim`, `hidden_crouch` | assassin | Precision attacks and Long Shot, Hidden |

27 Hero sprites in total (7 shared x 3 classes + 6 class-specific).

## VFX (canvas 128 x 128, anchor 0.5, 0.5)

`vfx/muzzle_flash`, `energy_projectile`, `shotgun_blast`, `shield_ring`, `cover_deploy_effect`, `drone`, `mark_reticle`, `slow_indicator`, `reactor_pulse`, `explosion`.

## Manifest

`assets/manifest.json` is a PixiJS asset manifest (one bundle per folder: `heroes.<class>`, `vfx`). Each asset has an `alias` (`<bundle>.<name>`, for example `heroes.bruiser.idle`), a relative `src` and `data.anchor`. The game loads only through the manifest. When final assets are packed into atlases, the manifest changes, the aliases do not.

## Rendering notes (from the 45 x 25 Grid)

- A full Grid is 4480 px wide at 128 px tiles ((45 + 25) x 64). On a phone the board is therefore scaled down; the UI spec defines the camera behaviour.
- Depth sorting by the rotated depth of the anchor tile (`row + column` at the 45 degree view; skill `depth-sorting-occlusion`).
- Tile centre for grid cell `(col, row)`: `x = (col - row) * 64`, `y = (col + row) * 32` (skill `isometric-grid-math`).
